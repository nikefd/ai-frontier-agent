# 按 Harvard CS2680 建设交互学习路径

日期：2026-11-16。用户已明确倾向以该课程为主线；本文件是实施计划，不能当作课程功能已上线。

## 1. 决定与范围

以 Harvard CS2680 Modern AI Systems: Agents and System Optimizations（Fall 2026）的五项作业顺序组织学习。先观察现成编码 Agent，再构建循环、优化 Harness、接管模型服务，最后联合优化。原课程资料与作业入口见文末。

现有文章 Agent 保留为真实应用案例和可观察事件的技术基础。课程的编码任务、隔离环境、补丁与测试不能全部替换为文章检索。此前“先做上下文策略对照”的建议调整为第三阶段中的候选实验，不抢在第一、二阶段前面独立开发。

不恢复已撤下的模型目录、上下文解剖台和旧日志浏览页面。课程学习围绕能操作的任务与证据逐步展开，主入口只在第一条完整课程练习可用时加入网站，避免先上线空目录。

## 2. 五阶段交付

| 阶段 | 课程目标 | 网站中的操作与可视化 | 验收证据 |
| --- | --- | --- | --- |
| 1 · Mads-Lens | 观察现成编码 Agent | 输入真实代码任务，实时观察读取/命令/修改；逐调用状态与输出、轨迹目录、同会话续问，存在子任务时显示可折叠树 | 一次实际编码运行、一次真实失败、一次实际续问；真实子任务另需采集验证，缺失不能画成已发生 |
| 2 · Mads-Loop | 构建自己的 Harness | 在隔离代码环境完成读取→模型建议→执行→回填→验证；检查真实请求及循环停止原因 | 可独立运行的 Harness、统一事件、实际补丁与隔离测试结果；明确哪些是我们的扩展实现 |
| 3 · Mads-Opt | 测量并优化 Agent | 用固定任务比较上下文、工具设计、预算分配与模型路由；需要时再尝试记忆/并行 | 基线与改动版本、固定任务/代码版本、配置、重复运行记录及效果/消耗差异；不预设复杂结构更好 |
| 4 · Mads-Serve | 自托管模型并定位服务瓶颈 | 把同一个 Agent 接到自有模型服务，联合查看 Agent 时间线与实际服务指标 | 实际服务端点、模型/引擎版本、GPU规格、真实运行日志及周期采样指标；未采到的项标未知 |
| 5 · Mads-Stack | 优化全栈并泛化任务 | 在 Agent/模型/服务配置之间做可复现实验，解释完成任务数与端到端时间的变化 | 保留成功和失败改动、多次运行、最终任务状态检查；从编码任务扩展至终端任务 |

表中网站设计是本项目方案，不是哈佛额外要求。正式作业要求和可用资源以原页面为准。

## 3. 第一阶段先做透

### 学习者真正操作什么

选择一个带测试的小型真实代码库的隔离副本，提交“修复具体失败测试”或“增加一个有验收条件的功能”。首个库应能理解、有实际故障且运行成本可控，不使用用户整个工作区或私人会话。

首先直接观察 Claude Code 的真实事件流，明确“我们控制的是呈现与任务环境，尚未替换它的内部循环”。第一阶段不把现有 DeepSeek Harness 改个名称当作 Claude Code；DeepSeek 自建循环放在第二阶段。Codex 适配可以以后扩展，不作为第一阶段必须同时实现的目标。

### 同一练习中的画面

1. 任务与运行状态：目标、工作目录的公开别名、运行中/完成/失败/已停止；只有真实结果支持时才显示完成。
2. 主轨迹：助手可见文字、工具用途/实参、pending/running/result/error状态；原始 ID 可展开，不作为主标题。
3. 环境结果：真实文件差异、命令输出与退出码、测试结果。测试与补丁对应同一任务版本，运行中产生的测试不能被替换成预设成功。
4. 轨迹目录与树：宽屏可定位调用，窄屏折叠；子任务按实际父调用关联，平面运行保持平面。子任务标为“本次未发生”时不补演示节点。
5. 续问：任务后追问沿原会话继续，能看到新一轮增加了哪些动作，而不是把整段提示重新提交并称为续问。
6. 数字与证据：只显示 CLI 实际提供的时长、轮次及费用；缺失不估零、不按调用数量猜费用。

遵循用户已确认的阅读偏好：执行过程在上、成果在下；成功后过程自动收起且可重开；失败/停止保留过程；标题使用动作与对象，协议标识移入详情。

### 开发与验收顺序

- 先从明确选定、可公开处理的记录开发事件适配器与回放，复用现有流式接收、转义/Markdown、折叠和状态模式。
- 再接受控执行环境与 CLI，会话控制和原始数据隔离放后端/运行节点，浏览器只读事件、发任务与控制指令。
- 验证普通成功、失败、续问与含真实子任务四条路径。只有实际验证过的路径才标“可用”。
- 最后给每条轨迹加少量原创建议问题，例如“第一次测试失败后，它读取了哪个文件？”答案必须能跳到具体证据。

现有一次 Codex 修复记录和一次 Claude 未登录记录不满足上述 Claude 成功/续问/子任务验收。此前两次受控 CLI 运行授权已使用；本次计划没有启动新的编码 Agent、读取私有历史或更改登录。后续真实 CLI 实验沿当前会话的运行授权约束执行。

## 4. 第二至第五阶段的资源与配置区别

- 官方第二作业指定了模型与评估方式；本项目可提供自有 DeepSeek 实验配置，但须标“适配实验”，不可声称符合原课程指定模型的结果。课程 proxy、账号、排行榜和隐藏评估不能当作公共服务。
- 编码任务需要与网站进程分离的受控运行节点。复用课程公开 starter 前先检查实际可下载性与许可；不能预先假定我们具有全部材料或再分发权限。自备练习明确标原创，不包装成官方题。
- GPU 阶段需要自有/获准的模型服务与计算资源。课程计算资源不向普通旁听者提供；不因为网页上能读教程就认为能使用其集群。
- 仅接 DeepSeek API 时展示可获得的应用侧请求/响应和提供方报告指标。GPU 利用率、服务排队、显存和 KV-cache 内部状态只有真实采集后才能展示。模拟实验须单独标注，不能充当测量。
- 不自动购买 GPU、下载大型任务镜像或重新配置生产执行权限。到相应阶段先给出具体资源需求与可验证环境。

## 5. 保持 clean architecture

按功能组织课程实验，沿用现有清晰边界，不提前建设通用编排平台：

- 课程定义：学习目标、原资料链接、练习入口及验收条件，只是内容数据。
- 任务环境适配器：负责创建/停止隔离任务、读取差异与测试产物，不渲染 UI。
- Agent 适配器：第一阶段接现成 CLI，第二阶段接自建 Harness，输出明确来源的规范事件；保留原始记录供核对，不丢字段装成完全相同协议。
- 运行用例：控制会话、生命周期、限额、取消、资源释放；路由只做身份与参数处理。
- 事件投影：同一事件源生成主轨迹、目录/树、检查器与指标；呈现不伪造执行状态。
- 后续服务指标采集器独立接入，不能把 GPU 采样逻辑塞进聊天组件。

每阶段保留可回放的审查后样本和独立测试。回放用于快速UI验证；真实运行用于验证时序、续问与执行，二者明确区分。
