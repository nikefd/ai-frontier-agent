# AI Frontier 可视化学习网站计划

日期：2026-11-11。状态：**用户已于 2026-11-11 批准按计划推进；2026-11-11 用户进一步授权连续完成 M1–M5，无需逐阶段 review。**

本文件保留已批准的产品目标。M0–M5 的首版能力已实现，当前实现范围与边界见第 10 节。现有资讯站继续保留。用户已授权连续完成，不再等待逐项 review。

## 1. 目标与产品主线

从“每天了解 AI 新进展”，逐步延伸到“看懂模型如何接收上下文、Agent 如何使用模型和工具，再通过小实验理解差异”。

网站由五部分组成：

| 入口 | 用户想解决的问题 | 主要交互 |
| --- | --- | --- |
| 今日进展 | 最近发生了什么？ | 保留速报、文章、原文引用 |
| 模型库 | 有哪些模型，各有什么区别？ | 搜索筛选、详情、并排比较、进入实例 |
| 上下文解剖台 | 一次请求到底发了什么？ | 导入请求、组成占比、消息与工具关联、差异对照 |
| Agent 图谱 | 一个 Agent 是怎样组成和执行的？ | 部件图、执行轨迹、逐轮请求、实现与协议关联 |
| 学习案例 | 我如何从看懂走向会用？ | 问题驱动案例、修改输入、观察差异、自检 |

主线：**资讯 → 模型/Agent 详情 → 可探索案例 → 原始请求和结果 → 小实验**。页面通过稳定 ID 关联，不做五个互不相通的栏目。

## 2. 模型库：覆盖广，学习深度分级

“各种模型都有”采用可持续扩展的目录，而不是只做三张模型卡，也不承诺穷尽全球所有模型或每个微调权重。

### 覆盖维度

- 商业与开放权重模型，国内外提供商，模型系列与具体版本。
- 文本/代码/推理、多模态、图像、音频、视频、embedding、reranker。
- 在线 API 与可本地部署模型；区分原厂模型、托管商、API 协议，避免把同一模型重复当成不同模型。
- 在用、预览、弃用与停止服务状态；保留历史版本和迁移关系。

初始提供商候选包括 OpenAI、Anthropic、Google、DeepSeek、Qwen、Meta、Mistral、xAI、Kimi、GLM、MiniMax、字节 Seed 等；这是覆盖候选，**具体在用型号与能力须实施时核验官方来源**。开放权重与专用模型按任务类别补充。

### 每条模型记录

- 名称、提供商、系列、版本/别名关系、任务类型、状态。
- 输入输出模态、工具调用/结构化输出等能力、上下文与输出限制；能力可标未知或依部署而异。
- 官方 API/模型卡/权重/许可链接、发布时间、最近核验日期。
- 定价与限制按“提供商 + 接口 + 时间”记录，没核验的不填；不把上下文上限等同于有效记忆能力。
- 关联资讯、协议、教学案例；哪些内容已完成可视化、哪些只有资料条目，明确标出。

### 深度分级

1. **目录级**：可搜索，有可靠来源与基本属性。
2. **协议级**：有该协议适用的请求、响应和工具调用示例。
3. **案例级**：有经过检查的完整轨迹、可视化解释和练习。

同协议可复用解释，但不能因此声称每个型号都实测支持。第一批争取覆盖约 10 个提供商、30–50 条有来源的代表记录；这只是初始规模，不是最终范围或验收的唯一指标。

## 3. 上下文解剖台：以 Inspector 为交互质量参照

参考：https://inspector.zhangyangbin.com/ 。借鉴“输入可解析、结构可检查、调用可关联”的体验；是否复用源码取决于源码可用性与许可，不复制参照中的个人路径、会话或未授权内容。

### 请求分析

- 粘贴 JSON、导入本地文件、选择教学示例；明确支持的协议，无法识别时提示，不静默误解析。
- 第一批覆盖 OpenAI Chat Completions、OpenAI Responses、Claude Messages、Gemini GenerateContent 四种协议家族；每个适配器单独验收。
- 展示 system/developer、工具定义、消息历史、工具结果和其他请求字段的组成。
- 占比先使用**明确口径的 UTF-8 字节数**；不得把字符数或估计值显示成真实 token。token 数仅在有匹配 tokenizer 或原始 usage 时显示，并说明口径。
- 点选组成图的一个块，定位到原文与解释；双向联动，不只展示彩色装饰图。
- 工具支持描述、参数树、原始 schema；识别必填、嵌套对象、数组及不支持结构的原样回退。
- 按原始顺序展示消息；按用户轮次分组属于辅助视图，注入消息、工具结果、并行调用不强行算成新用户回合。
- 用 ID 关联工具调用与结果，突出未匹配、重复 ID、缺失和错误返回；允许一个模型步骤包含多个工具调用。
- 展示可观察的缓存标记、thinking 配置和上下文管理字段；对未知字段保留原文，不推测隐藏思维。

### 修改与比较

- 选择两个请求，比较新增/移除/修改的消息、工具定义与体量。
- 在副本中移除 system 或工具定义，展示结构和占比变化；保留原始输入并能恢复。
- 解释修改可能影响什么，但不凭静态修改伪造“模型会如何回答”。如果修改破坏调用/结果关联，显式提示。
- 用“skill 内容从哪里加载、被放到哪里”解释技能。不同产品可能将其注入消息、作为文件读取或通过专门机制暴露，不硬编码为通用 `skills` 字段。

### SSE / 流式响应

- 单独导入流式输出；支持事件时间线、原始事件、按协议重组文本与工具参数。
- 覆盖分片、并行工具、结束原因、错误、中断与无法解析事件；输入无时间戳时只显示顺序，不伪造耗时。
- usage/cache 数值仅来自输入实际字段；不由签名恢复隐藏推理。成本只有在型号、费率与核验日期明确时计算，否则显示无法计算。
- 不通过 eval 执行内容，不自动抓取导入数据里的 URL；解析在浏览器本地，不上传、不进入分析日志、不自动长期保存。

## 4. Agent 图谱：产品、框架与模式分开讲

### 分类与首批候选

- **产品型 Agent**：如 Claude Code、Codex、Gemini CLI、OpenCode；每项以当时公开实现/文档为准。
- **框架型 Agent**：如 OpenAI Agents SDK、LangGraph、PydanticAI；解释它们提供的运行机制，而不是把框架当成一个模型。
- **通用模式**：工具调用循环、RAG、计划与执行、工作流、子 Agent/交接、多 Agent 协作。

首批做 3 个有充分资料支持的代表性实现和 3 个通用模式，再扩展目录。闭源产品只展示公开可验证的部分，未知部件明确留白。

### 一个 Agent 详情页

1. 一张可点击部件图：模型、指令、工具、skill、记忆、检索、编排与权限。
2. 每个部件说明职责、输入输出、上下文是否可见，以及来源。
3. 一条任务轨迹：用户目标 → 请求 → 模型输出 → 工具/子 Agent → 结果 → 后续请求 → 停止。
4. 选中某一步，直接进入解剖台看该轮上下文；能比较前后两轮，而不是只播放动画。
5. 标注证据类型：人工教学示例、真实脱敏运行、依据公开源码整理、未知；不能混用。
6. 解释失败与边界：工具报错、权限拒绝、循环次数、上下文膨胀、记忆召回失效。

## 5. 学习案例与交互标准

第一条完整案例围绕“查资料并回答”展开，再增加“修改代码并测试”“加载skill执行任务”“检索记忆”“工具失败恢复”“子Agent交接”。

每个案例具备：学习目标、前置概念、可探索轨迹、原始数据、修改对照、一个自检问题、官方参考与局限。

界面按用途分为“引导学习”和“自由检查”，共享同一数据与解析器。引导模式解释每一步；检查模式供用户粘贴自己的数据。桌面三栏或双栏联动，手机使用分区切换，保证内容可读。必要的树、占比图、调用连线、差异高亮必须具有数据含义。

验收不再以“有几个按钮、能展开JSON”为完成标准，而是看用户能否回答：**这轮模型看见了什么？新增了什么？哪个工具结果对应哪个调用？skill在哪里？为什么下一轮变大了？**

## 6. 实施阶段与验收闸门

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| M0：体验样板 | 一个真实可交互的高保真样板，使用安全教学数据，包含目录入口、部件图和请求联动 | 用户亲自 review，确认方向达到 Inspector 参照；不再先铺很多页面 |
| M1：请求解剖核心 | 完成 Chat Completions 与 Claude 两个适配器、本地导入、组成图、参数树、调用关联、请求对照 | 两种协议分别有正常/缺失/异常测试；恶意字符串不能执行；私有输入不上传；桌面/手机验证 |
| M2：模型库与协议扩展 | 模型目录、筛选对比、来源核验；Responses 与 Gemini 请求适配器 | 四种协议可明确区分，模型有出处/核验时间，目录项直达适用案例，未验证能力不标支持 |
| M3：流式轨迹 | 按四种协议分批完成 SSE/流式解析与请求关联，覆盖完整和中断案例 | 重组结果可与固定样本对照；工具参数不串线；未知事件不丢失；不伪造usage与耗时 |
| M4：Agent 图谱 | 3个代表实现、3个模式、至少3条完整学习案例 | 点击部件与运行步骤能定位到具体请求/结果；证据与版本明确；失败案例至少1个 |
| M5：学习网站闭环 | 资讯关联模型/Agent、案例练习、阅读进度与内容维护流程 | 从一条资讯进入对应案例并完成自检；已有资讯功能回归通过 |

按用户最新授权连续实现，完成后统一验证并交付；后续扩充内容也遵循证据与来源要求。

## 7. 内容维护与技术边界

- 复用现有 FastAPI/Vite 和中英文能力，不另起一套账号、站点或框架。
- 解析器、教学数据、模型/Agent目录、页面渲染分开；按协议写适配器，不在现有巨型视图模块里继续堆逻辑。
- 目录起步用版本化结构化数据，配校验脚本；后续确有需要再增加编辑后台。字段记录来源与核验日期，过期信息显示待复核。
- 模型发现可辅助自动化，关键能力、价格、许可与弃用信息人工确认后展示；不把聚合商字段当最终事实。
- 初期以离线学习为主。真实模型运行、用户密钥、计费、多模型自动评测等另开范围；不要求用户先配API才能学习。
- 导入数据可能包含敏感内容：本地内存处理、显式清空、容量限制、安全文本渲染；不默认上传或保存。公开案例单独脱敏和核验授权。
- 对已有实验室、学习路径、上下文实验室统一命名与导航，避免用户看到多个不知区别的“实验室”。

## 10. M1–M5 首版交付

- `/academy`：40 条模型资料、13 个提供方，搜索/类型/部署筛选、最多三项比较、来源与核验日期；超过 30 天提示复核。状态、价格、许可等未核验字段明确标注，历史退役版本与自动追踪留待内容持续维护。
- `/context`：四协议 JSON、文件导入、组成定位、参数树、ID 关联、异常提示、副本删改、任意两份请求比较；原始未知字段保留。字节口径明确，不估算 token。
- 流式模式：四协议常见 SSE 与 Gemini JSON chunks，文本与工具参数重组、usage/停止/错误、原始事件、可选请求关联。Gemini partialArgs 扩展仅保留原文并警告；不是所有服务商扩展的完整协议验证器。
- Agent 图谱：Claude Code、Codex、Gemini CLI、LangGraph 与工具循环/记忆检索/任务交接三种模式，部件可点选；公开资料整理和通用教学轨迹分开标注。
- 五条案例：查笔记、改代码并测试、工具错误恢复、记忆检索、子 Agent 交接；逐轮检查与解剖台深链、预写结论、自检、本浏览器完成标记。skill 加载在引导学习的独立开关中演示。
- 资讯与速报按确定性名称匹配关联目录；未命中时不猜测实体。原有抓取、速报、实验和账号沿用。
- 请求上限 1 MiB、流上限 2 MiB/5000 事件、200 消息/100 工具/500 上下文块。解析器、协议 fixture、目录、案例和视图分离；维护流程见 llmdoc/guides/learning-content-maintenance.md。

这次完成的是计划的首版离线学习闭环；不包括真实模型执行、自动性能评测、用户密钥、全世界模型穷举或产品内部隐藏状态。
