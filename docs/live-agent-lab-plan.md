# 真实 Agent 可视化实验台：重新设计

日期：2026-11-12。状态：完整实验台仍是设计提案；已先交付文章页基础 Agent 真实检索与执行可视化，并完成真实 DeepSeek 验证。单步与分支尚未实现。旧运行拆解、模型学习库、上下文解剖台已撤下。

## 1. 产品判断

之前的失败是把资料浏览器当成学习工具：读解释、点步骤、展开 JSON，仍然无法亲手验证因果。新版本只做一个工作台，用真实 DeepSeek 请求完成有用任务，让用户看见执行过程，并能在明确的边界改变输入、重新实验。

核心验收不是“有流程图”，而是用户能回答：这一轮模型实际拿到了什么？谁执行了工具？结果怎样进入下一轮？拿走一条证据或换一条规则后，后续行为有何变化？

## 2. 第一个真实任务

“从本站最近七天的文章里，找出最多三项会影响现有 API 调用的变化，列出依据和应对建议。找不到就明确说证据不足。”

用现有资讯解决每天会遇到的问题，不另造教学仓库，也不把天气/算术的预写结果当价值。输入可以改。第一次运行冻结可访问文章清单和内容快照，分支沿用它，避免新闻库变化干扰比较。本站覆盖不等于全网覆盖；时间范围、可用篇数、来源与缺失正文必须可见。

只提供两个真实只读工具：search_articles（在本次快照按关键词/日期查询）和 read_article（按快照内 ID 读取正文或已有摘要，标明具体来源）。工具输出由实际数据决定，不由模型或演示脚本预先编好。现有工具若返回格式不适合教学，只适配其输出，不复制抓取与检索逻辑。

## 3. 屏幕构成：主画面是正在工作的系统

桌面主要区域占屏幕约 70%，右侧检查器约 30%。不再采用长篇讲义加下一步按钮。

```text
┌ 任务输入 / 开始 / 单步 / 连续 / 停止 / 本次消耗 ────────────┐
│                                                        │
│  本轮模型收件箱       DeepSeek          执行环境          │
│  [系统规则] ───────► [等待响应] ──────► [工具请求队列]    │
│  [用户任务]          [文字 / 调用]       search_articles │
│  [工具定义]                              read_article  │
│  [此前消息] ◄──────── [工具结果回填] ◄── [真实文章快照]   │
│                                                        │
│  Turn 1 ── read ── Turn 2 ── search ── Turn 3 ── 回答   │
└────────────────────────────────────────────────────────┘
                             │ 点击任意消息/调用/结果
                             ▼
                  检查器：实际值 / 来自哪里 / 去了哪轮
```

- 收件箱是本轮实际请求的结构视图，能看到具体消息内容和工具定义，不是凭历史猜出的 prompt。进入请求后标记“本轮已发送”，配置后改不追溯修改它。
- 工具卡片显示 waiting/running/succeeded/failed、实参、输出及同一 call ID。调用与结果是一对，可沿线定位；模型输出本身不能点亮“已执行”。
- 结果回填后，新卡片进入下一轮收件箱；新增项高亮，旧项保留。按需展开原始 payload，默认显示可读正文和类型。
- 下方时间轴是执行事件的投影，能回看已发生状态；回看不触发 API。实际耗时与回放动画分开标识，尊重减少动态效果设置。
- 右侧只解释所选对象的“内容、来源、用途、下一站”。不常驻整页术语说明，不把模型可见的内容与服务器凭证混在一起。
- 手机用三个切换面板“上下文 / 正在执行 / 结果”，保留同一个事件状态，不硬塞缩小的桌面图。

## 4. 两种真正有意义的交互

### 单步运行

1. 组装请求后暂停：用户检查本轮将发给 DeepSeek 的内容。
2. 点击“发送这一轮”：真实 API 返回文字或 tool_calls，画面按实际响应推进。
3. 有工具调用时暂停：展示参数；用户点击执行，服务器运行白名单工具。
4. 收到工具结果后暂停：用户检查输出以及准备回填的消息。
5. 点击继续：实际发送下一轮，直至最终回答、错误、用户停止或达到上限。

多工具调用按完整的 assistant 消息及其结果维护协议配对；有一项失败也显式回填对应错误，不能丢失 ID 或只截取第一项。普通流式分片尚未完整时不允许执行工具。

### 从请求边界分支比较

选择一轮尚未发送或历史已发送的请求，复制成新分支：修改系统规则、用户任务，或在工具结果尚未产生的起始边界禁用工具。保留主线历史；分支从该边界重新真实调用 DeepSeek。第一版不允许随意删掉已有 tool_call 的结果，避免造出非法消息序列。

比较固定文章快照下的两个分支：请求差异、实际工具选择、引用是否属于快照、答复差异、调用轮数、耗时、API 报告的 token。重跑是新的付费调用，不能叫“撤销”。模型有随机性，一次对照不证明唯一因果。

手工篡改工具结果、故障注入、上下文压缩、多 Agent 等暂不做；等单条真实闭环可用后再决定。首版不加模型目录和课程系统。

## 5. DeepSeek 接入与证据口径

复用项目已有服务端 DeepSeek 配置（AIF_LLM_API_KEY / DEEPSEEK_API_KEY），密钥不返回浏览器、不进入日志、事件或导出。此提案没有读取或迁移密钥。实现时检查当前模型配置及能力，不把旧别名、参数支持或价格写死。

官方资料：
- https://api-docs.deepseek.com/guides/tool_calls/ ：模型返回工具请求，应用负责执行并回填。
- https://api-docs.deepseek.com/guides/thinking_mode/ ：思考模式与工具使用的历史回传规则有特别要求。

第一版优先使用核验支持工具调用的非思考模式，明确设置模式并按实际返回保存所有必要协议字段。以后增加思考模式要单独处理回传规则；API 提供的 reasoning_content 与教学解释分开，不声称展示模型完整内部机制。

捕获位置在实际 HTTP 序列化边界：完整 JSON 请求正文和响应正文/分片，不捕获 Authorization 请求头。服务端如果添加语言规则、截断、过滤，必须发生在捕获之前，防止界面展示的 payload 与真正发送的不同。每次调用记录模型、配置、轮次、请求 ID（有时）、usage、错误与时间。

token 数值只用 API 报告值；每块消息只标字符/字节，不把字节包装成 token。缓存命中字段按 API 定义展示，不重复加到输入。没有可靠定价及生效版本时不显示臆测费用。

## 6. Clean architecture 与 clean code

按这个功能自成目录，依赖向内，不引入一套全站通用工作流框架：

| 边界 | 唯一职责 | 不应依赖 |
| --- | --- | --- |
| 领域状态机 | phase、turn、消息/调用配对、下一步是否合法 | FastAPI、DOM、httpx |
| 运行用例 | 发送一轮、执行工具、分支、停止，编排状态迁移 | HTML/CSS |
| DeepSeek 适配器 | 序列化、请求、响应/usage/错误解析，生成真实记录 | 页面布局 |
| 工具适配器 | 调用既有文章服务，输出明确来源 | 模型调用与 UI |
| HTTP 路由 | 身份检查、输入校验、用例调用、事件流 | 检索实现 |
| 前端状态与投影 | 从同一事件状态生成画布、时间轴和检查器 | 自行猜测工具是否执行 |

一个事件源，三个视图。没有第二份手工编排的“演示步骤”，不分别维护图与日志的状态。事件至少携带 run_id、branch_id、turn_id、call_id（适用时）、顺序号和类型。UI 只投影已收到事件，动画不改变业务状态。

第一版运行状态限时保存在单进程内存，按用户隔离且有容量上限；服务器重启/超时明确显示运行已结束，不伪装能恢复。要长期保存才加存储适配器，JSON 写沿用 write_json_atomic。运行命令带版本校验，重复点击不能重复付费执行，同一分支同时最多一个请求。

## 7. 边界与验证

首版仅管理员使用，沿用现有身份与权限；每次任务有明确调用轮次/输出长度/超时上限，预算策略可配置。工具只读快照，不接 shell、任意代码或任意 URL。用户点击开始才调用 API；停止会阻止后续调用，已发生消耗不能撤回。取消/断连产生真实结束状态，不能补一个伪成功。

自动测试验证状态机、调用/结果配对、非法/重复操作、用户隔离、分支快照一致、请求捕获与实际发出正文一致、错误和取消。不把 mock 响应当成真实端到端成功。

人工验收只认这些结果：
1. 一次真实 DeepSeek 任务有至少一次真实工具往返；若模型没有选择工具，如实显示，不能伪造。
2. 用户能指出第一轮没有的哪条证据进入了第二轮，并打开实际发送正文核对。
3. 同一文章快照下，从合法边界做一次真实分支，能看到输入与结果的差异，而不预设结论。
4. 中英文及390px可操作，状态不只用颜色表达，键盘可选择消息、执行与暂停。

## 8. 实施顺序

先完成状态机与 DeepSeek/文章工具适配器的真实闭环，再把真实事件接到三栏画布，随后做单步控制与分支对照，最后才加视觉动画。每一阶段用同一个真实任务验收。现阶段交付本设计与旧功能移除；尚未建设或上线新的实验台。
